## 设计决策：提醒/日程为何自建而非用系统日历（17:48 讨论）

用户问「为什么不用系统的日程和提醒」。结论：保持自建（本地加密 `SecretVault` + `AlarmManager` 精确闹钟 + 自建通知），不改。理由：

- **隐私**：提醒文案是用户语音原话。写进系统日历会随账号（Google/华为/Exchange）同步上云，等于把听到的话外传；现在这套不出设备。
- **权限轻**：只需通知权限，无需 `WRITE_CALENDAR` + 账号选择流程。
- **国产 ROM 可靠性**：EMUI/MIUI 对第三方后台卡得死，插进系统日历依赖系统日历 App 按时弹，常被限制/关同步/未登录；`AlarmManager` 精确闹钟由自己持有、自己 `rescheduleAll` 重排，行为可预期。
- **场景匹配**：语音助手要的是「说一句→到点弹通知」的轻闭环，不是跨设备/邀请/复杂重复规则的日程管理；系统日历 UI 重、字段多，杀鸡用牛刀。离线也能建能响。

系统日历适合的场景（跨设备同步、长周期、复杂重复、多端互通）目前不是需求。若以后要，可加「可选同步到系统日历」开关（需日历权限），默认仍走轻量本地提醒。用户答复「先这样吧」，暂不实现。
